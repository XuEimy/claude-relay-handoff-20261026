# 基础服务与接入边界

## 本地已实现

| 服务 | 当前行为 |
| --- | --- |
| 账户 | 邮箱+密码注册、登录、退出、修改密码、管理端禁用；首次管理员初始化；注册记录说明确认版本 |
| 会话 | 服务端保存，按用户授权查询；搜索、重命名、删除、继续多轮对话 |
| 模型 | 多渠道、多模型显示与选择、启停；当前支持 Anthropic Messages 协议 |
| 回复 | SSE 转发、Markdown、停止生成、错误反馈；未配置渠道不会生成假回复 |
| 余额 | 整数微元存储，1元=1000000单位；开始前预留、结束后按已报告用量结算；不使用浮点余额 |
| 用量 | 输入/输出token、费用、请求状态；展示北京时间；当前页面查询最近100条 |
| 充值 | 单次兑换码、管理员充值及备注流水；兑换原子更新，不能重复使用 |
| 在线支付 | 支付宝网页跳转、微信Native二维码、订单查询、通知验签、金额与商户核对、重复通知幂等入账 |
| 管理 | 用户、模型渠道、费率、兑换码、订单、调用日志、操作审计；密钥不返回前端 |
| 基础保护 | HTTPOnly会话、同源写请求、角色校验、参数/大小限制、进程内限频、单用户单并发、120秒超时 |

金额计算：费率以“元 / 百万 token”配置，则 `token数 × 费率` 得到微元数量。结算向上取整为整数微元；前端用量展示4位人民币小数，数据库保留6位精度。余额卡展示2位。

预留使用上下文UTF-8字节估算加冗余量，以及最大输出额度；不足时拒绝发送。超出预留的上游异常费用由运营方承担。中断时只结算已收到的用量，不对未报告部分进行估计收费；服务重启释放未完成预留。正式运营需与上游账单核对这一成本策略。

## 支付配置

所有真实凭据只填写服务端 `.env`，不发到聊天或前端。多行 PEM 可使用带引号的环境变量或 `\n` 转义。当前仅实现普通商户模式。

支付宝需要 `ALIPAY_APP_ID`、`ALIPAY_SELLER_ID`、`ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`。使用官方 Node SDK，RSA2签名；通知校验签名、商户、应用、订单号、金额和成功状态。默认示例打开沙箱，正式切换需显式设置 `ALIPAY_SANDBOX=false`。桌面使用page.pay，移动使用wap.pay，商户需分别具有对应产品权限。

微信需要 `WECHAT_APP_ID`、`WECHAT_MCH_ID`、`WECHAT_SERIAL_NO`、`WECHAT_PRIVATE_KEY`、`WECHAT_PUBLIC_KEY`、`WECHAT_PUBLIC_KEY_ID`、`WECHAT_API_V3_KEY`。使用公钥模式；校验返回及通知签名、时间窗、公钥ID，解密AES-256-GCM报文，再校验商户/应用/币种/金额/订单号。平台证书自动轮换模式尚未实现。

回调地址由 `PUBLIC_ORIGIN` 派生：
- `/api/payments/alipay/notify`
- `/api/payments/wechat/notify`

用户点击支付只是创建订单和打开收银台；同步跳转不入账。只有服务端验签通过的通知或查单结果才可入账。同一订单重复通知不会重复加余额，交易号也有唯一索引。未配置商户时前后端均拒绝下单。

微信当前为Native扫码，移动设备需另一个设备扫码；微信内JSAPI、手机H5支付尚未实现。支付宝支持桌面和移动跳转。当前提供查询与通知补偿，不含定时下载支付账单、自动退款或发票。

## 后置接入与当前限制

用户已明确域名和服务器不着急，因此未购买、绑定或发布任何站点。

- 真实模型、支付宝/微信商户、HTTPS回调与真实支付验收尚未完成。
- 尚未接入手机号/短信、邮箱验证、忘记密码邮件、自助注销、客服工单；当前已有登录密码修改。
- 暂无附件/图像/语音处理、Web搜索、工具调用或公开API Key分发。当前产品定位为网页文字聊天。
- SQLite和进程内并发/限频适合单实例功能验证；未进行负载、灾备、分布式部署或渗透测试。反向代理下限频按连接来源，未盲目信任任意X-Forwarded-For。
- 运营主体、备案展示字段、正式政策、客服邮箱及面向实际运营的内容治理尚待确认和接入。当前政策页明确标为预览说明；不能将本地功能完成等同于已经符合全部公开运营条件。
- 存储目录含用户对话；数据库备份和加密密钥需要单独管理。当前只加密渠道凭据，不是数据库全文加密。

中国大陆适配已做的是中文交互、人民币与时区、本地字体和图形资产、两种常见支付协议及运营字段；网络可达性和服务商可用范围仍需在选定部署环境验证。
