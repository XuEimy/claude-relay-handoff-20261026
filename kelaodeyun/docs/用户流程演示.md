# 用户使用与充值流程演示

演示时间：2026-10-26，北京时间。所有操作在本机日常Chrome中完成。

- 管理后台：<http://localhost:4176/admin>
- 用户账户：<http://127.0.0.1:4176/billing>
- 原始预览：<http://127.0.0.1:4174/>，未混入演示账户、模型或余额。

4176使用独立 `data/demo.db`。页面顶部始终标注演示环境。模拟支付不会访问支付宝/微信服务器，不是真实支付沙箱；回复也来自本地固定事件，不代表真实模型效果。

## 初始化口令

当前本地开发环境无需初始化口令，页面已改为直接提示无需口令。首次设置管理员的邮箱、昵称和密码即可。

正式生产环境通过服务端 `SETUP_TOKEN` 配置初始化口令，用来保护首个管理员创建。它不是登录密码。生产环境仍强制验证此口令。

## 已实际演示的流程

| 步骤 | 结果 | 用户余额（元） |
| --- | --- | ---: |
| 创建演示管理员，配置演示模型和费率 | 后台可见1个演示模型 | — |
| 注册普通用户 `user@demo.test` | 普通用户看不到后台入口 | 0 |
| 使用后台生成的兑换码 | 20元单次兑换成功 | 20 |
| 选择支付宝50元，创建模拟订单并模拟成功 | 订单已到账 | 70 |
| 选择微信10元，创建模拟订单并模拟成功 | 订单已到账 | 80 |
| 发送对话 | 输入120 / 输出180 token；费用0.0066元 | 79.9934 |
| 管理员人工赠送5元 | 带备注充值记录可见 | 84.9934 |
| 返回聊天，打开历史会话 | 已保存的消息可重新读取 | 84.9934 |

模型演示费率：输入10元/百万token，输出30元/百万token。费用 `120×10/1000000 + 180×30/1000000 = 0.0066元`。

余额卡片显示2位小数，所以最终显示84.99元；数据库保留的实际余额为84.9934元。只读校验已确认：1条完成的用量、2笔已到账模拟订单、最终余额84993400微元。

## 两种视角

- 管理员：`admin@demo.test`。在localhost标签页登录。
- 普通用户：`user@demo.test`。在127.0.0.1标签页登录。

两个主机名让浏览器可同时保留不同角色的演示登录。生成的演示密码保存在项目根目录 `.local-demo-accounts.json`，文件权限0600，已由Git忽略。不要把这些账号或数据迁移到真实站点。

## 再次运行

`node scripts/demo-server.mjs`。脚本固定绑定127.0.0.1:4176、独立数据库；拒绝在NODE_ENV=production下启动。默认应用不注入模拟支付，不会出现“模拟付款成功”按钮。
